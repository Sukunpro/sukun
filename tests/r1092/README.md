# r1092 session preparation and speech policy

The Smart Session editor has an explicit, advisory Before you start check.
It reads existing personal/archive recordings and the current verified worker
cache, without starting audio, downloading media, taking a playback lease, or
writing settings/recordings. It explains the planned source; playback validates
it again. Missing and unavailable storage are distinct. Device speech,
multipart compositions and silence announcements retain explicit uncertainty.

Locked direct and favorite-linked private steps are omitted before labels or
recording keys are inspected. Source/queue/access changes retire old results.
Repeated source probes share reads within the check, not across new checks.

Smart-session explicit Arabic/Turkish device fallback shares the pure plan used
by the preview. Automatic recording priority, native completion and terminal
command ownership retain their existing contracts. Health inventory validation
has a finite 128-entry bound; corruption, approved-path, byte and concurrency
guards remain in force.

Controlled source suites are `preflight-cache.cjs`, `preflight-source.cjs` and
`preflight-ui.cjs`. Full-app suites are `preflight-browser.js`,
`smart-source-policy-browser.js`, `offline-preflight-browser.js` and
`health-runtime-browser.js`. Native browser checks use disposable profiles and
labelled generated recordings/device metadata. The offline suite installs the
real worker and verifies original cached MP3s. No physical Android locking,
microphone sound quality, Bluetooth or audible speech quality is measured.

`verification.json` contains only completed checks against the final frozen
release. Earlier failed/superseded evidence remains outside the repository.
