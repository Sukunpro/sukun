# r1251 alignment acceptance

`CHROMIUM_PATH=/path/to/chromium NODE_PATH=/path/to/node_modules node tests/r1251/alignment-browser.cjs . /tmp/r1251-evidence/report.json`

The exact-byte fixture loads a synthetic disposable Berhetiyye profile, using native application tab/session/Tekke owners. No real user credentials, audio, or recordings are used. Browser request routing disallows nonlocal external resources. The workflow pins the same checkout, artifact and Playwright versions as existing accepted repository workflows.

Matrix: Turkish and English × 320, 390, 768, 1440 and 1920 px. It captures screenshots and records bounding boxes for Discovery, Ambience headings, Frequency workbench/preset headings/cards, Zikir preparation, Arrangement, Notifications and Tekke purpose/Mihrab panels. Tests fail on missing visible target coverage, x-axis overflow, text outside frames, defined width caps/centering, hidden-control display regressions, SRI/page errors and source drift. Native selected-value width is checked separately because selects do not wrap text. It does not artificially require zero document vertical scroll.

This suite has only been syntax-checked locally: local Chromium launch is blocked by socket EPERM. A successful CI browser result and inspection of its screenshot artifact are required before claiming rendered acceptance. It does not establish physical Android behavior, operating-system fullscreen API behavior, enlarged text, screen-reader or acoustic acceptance. Existing current release/upgrade/offline gates remain required; this job supplements rather than replaces them.
